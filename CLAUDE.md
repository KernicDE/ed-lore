## Project Mission

**The GalNet Chronicle** is an AI-enriched archive of all Elite Dangerous GalNet articles (3301–3312+): 2,551 articles, 3,484 entity profiles, 30 story arcs, deployed as a static site at https://kernicde.github.io/ed-lore/.

---

## Commands

```bash
# Rebuild the data graph after editing any Archive/ or Entities/ file — required before the site reflects changes
python scripts/build_graph.py

# Validate article frontmatter before committing (required fields, banned topics, arc consistency)
python scripts/validate_enrichment.py

# Website dev server (from website/)
cd website && pnpm install && pnpm dev

# Local production build (rarely needed — GitHub Actions builds+deploys on push to main)
cd website && pnpm build

# Count archived articles
find Archive -type f | wc -l
```

There is no test suite. "Correctness" is enforced by `validate_enrichment.py` (data layer) and `pnpm build` (Astro type/build errors).

**Do not run** `python scripts/fetch.py` casually — it destructively re-downloads and overwrites `Archive/`, clobbering any in-progress enrichment. **Do not** generate audio locally — that's handled exclusively by the `audio-generation` GitHub Actions workflow.

Deploy is push-to-deploy: commit, `git push origin main`, GitHub Actions rebuilds the Astro site and deploys to GitHub Pages automatically. Monitor at https://github.com/KernicDE/ed-lore/actions.

## Architecture

**Two-layer system: flat-file data layer → generated JSON → static site.**

```
Archive/<YYYY>/<MM>/<DD>_<slug>.md   canonical article store (Markdown + YAML frontmatter)
Entities/{person,faction,location,technology}/*.md, Entities/Arcs/*.md   entity/arc profiles
        │
        │  python scripts/build_graph.py  (reads Archive/ + Entities/)
        ▼
lore_graph.json                              full graph — powers entity/arc static pages
website/public/data/galnet-meta.json         articles (no body_full) + entities + arcs — loaded async
website/public/data/galnet-bodies.json       {uuid: body_full} — lazy-loaded on article expand
website/public/data/search-index.json        search-optimized subset
website/public/data/version.json             build timestamp + counts, used for cache-busting query strings
        │
        ▼
website/  (Astro 6.2 SSG, static output, base path /ed-lore/)
  src/pages/            index.astro (timeline), chronicles.astro, map.astro, entity/[id].astro, arc/[id].astro
  src/components/       AppShell.tsx (React root), timeline/Timeline.tsx, audio/AudioPlayer.tsx,
                         context/ContextPanel.tsx, hud/SearchIsland.tsx, hud/CommandConsole.tsx, graph/EntityGraph.tsx
```

**Why the split JSON design:** `galnet-meta.json` is loaded first and drives the timeline UI without the ~3 MB of article bodies; `galnet-bodies.json` is fetched lazily only when a user expands an article. This keeps first paint fast despite thousands of articles.

**Audio is decoupled from the deploy artifact.** MP3s are generated by `scripts/generate_audio.py` (edge-tts, `en-GB-SoniaNeural`) and uploaded to a public Cloudflare R2 bucket (`ed-lore-audio`) by `scripts/sync_audio_to_r2.py`, hourly via the `audio-generation` workflow. The `AudioPlayer.tsx` component streams directly from `https://pub-4404b20907c141e1b68f3dc578038230.r2.dev/audio/{uuid}.mp3` — the Astro build never bundles audio.

**Article path convention:** `Archive/<in-game-year>/<in-game-month>/<in-game-day>_<slug>.md`, e.g. `Archive/3307/08/02_....md`. `uuid` in frontmatter is a deterministic UUIDv5 derived from `date + lowercase title`.

**Entity stubs vs. enriched profiles:** `build_graph.py` auto-creates `<!-- AUTO-GENERATED -->` stub entity files for newly-mentioned persons/factions. Enriched profiles must stay within 5% of `Entities/faction/alliance.md`'s length (the canonical style example) — trimming is manual only, never scripted. Full details in `AGENTS.md` §10.

**Two deploy triggers, one target repo:** `deploy.yml` (push to `main` → build Astro site → GitHub Pages) and `audio-generation.yml` (hourly cron → generate/upload missing audio → rebuild+redeploy site so new audio URLs go live). Both write to the same GitHub Pages target.

## Working with article data

- Enrichment (`summary`, `player_impact`, `modern_impact`, `entities`, `locations`, `topics`, `arc_id`) is added by hand, file-by-file — never via bulk script. See `.kimi/prompts/fetch-enrich-deploy.md` for the step-by-step workflow when importing a new GalNet season.
- Banned topics (remove unless clearly legitimate): `ship`, `sport`, `trade`, `construction`, `medicine`, `safety`, `treasure hunt`.
- After any Archive/Entities edit: `python scripts/build_graph.py` then `python scripts/validate_enrichment.py` before committing.

## Security & Secrets

This is a **public repository** — never commit API keys, tokens, or `.env` files. Cloudflare R2 credentials live only in GitHub Actions Secrets (`CLOUDFLARE_R2_TOKEN`). `.gitignore` already blocks `.env*`, `*.key`, `secrets/`, and generated `website/public/audio/`.
